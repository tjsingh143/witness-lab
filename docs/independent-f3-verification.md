# Independent F3 acceptance-integrity verification

**Verdict: NOT VERIFIED.** Reviewed commit `f9dd5d6efaa9d47f777215cd2bcb97ede5fa0bbf` on 2026-10-20. The original F3 relabelling is rejected, and valid baseline and mutant fixtures remain valid. ## Contract and source review

I read `PROJECT_BRIEF.md`, `docs/implementation-state.md`, `docs/acceptance-contract.md`, `docs/f3-acceptance-integrity-remediation.md`, `runner/contract.py`, `runner/analysis.py`, `runner/db.py`, and the relevant contract/unit fixtures. The brief requires evidence-backed, traceable acceptance. I1.7 requires corroboration of SQLite environment metadata with the canonical indexed session snapshot, including unfair or interrupted runs when an environment was recorded. A23 is the full-run acceptance assertion; root-aware `commissioning_gaps` uses the same run-contract path.

`runner/contract.py::_runs_checked` loads environment rows and session indexes and calls `_session_environment` before it excludes unfair or mutant runs. For a fair run, the helper requires exactly one canonical index, verifies file length and SHA-256, rejects duplicate JSON names, and compares the complete text-value map with SQLite and the run row. The actual writer's table-only `runs.clean_env` and early pre-v5 non-mutant format are allowed. These checks explain the successful original F3 and fair-run probes below.

The gap is the early return in `_session_environment`: `if not fair and not files and not present: return []`. It does not consider its `env` argument. Thus an unfair run with recorded environment rows can lose both its file and index and escape I1.7. `_runs_checked` then skips the fair-run session cardinality checks. A20 verifies indexed files of selected evidence and does not restore this obligation. The v5 append-only triggers do not change this verifier result; the contract explicitly says they are not relied on as proof.
